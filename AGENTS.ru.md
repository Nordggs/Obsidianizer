# Obsidianizer — правила разработки

## Назначение

Obsidianizer — автономный локальный инструмент, который подготавливает
сырые материалы для использования в Obsidian: структурирует файлы, обогащает
их метаданными и (опционально) резюме/тегами от LLM и формирует готовую папку
результата — при этом никогда не касаясь источника.

Он должен оставаться независимым от AI Chat Exporter. Два проекта не делят
код; взаимодействие происходит только через файловую систему (путь
`--source`).

## Критические принципы

1. Никогда не изменяй исходные файлы. Источник доступен только для чтения.
2. Никогда не удаляй файлы вне манифеста владения Obsidianizer.
3. Пары папок соседних этапов не должны пересекаться (`source`/`target` для
   импорта, `target`/`enriched` для AI-этапа, `source`/`enriched` как
   предохранитель) — совпадение путей или вложенность являются жёсткими
   ошибками.
4. Импорт никогда не вызывает LLM. AI-работа выполняется в отдельном этапе
   постобработки; его сбой не должен блокировать или портить результат импорта.
5. Процессоры регистрируются через реестр процессоров (registry).
6. Ядро конвейера не должно содержать специфики типов файлов.
7. Новые типы файлов реализуются как процессоры, никогда как хак в ядре.
8. Генерируемый результат должен быть детерминированным, где это возможно.
9. Манифест — журнал владения. Он пишется атомарно и только после того, как
   все остальные операции завершились успешно.
10. При кривом файле завершай аккуратно всю партию: сообщи о нём, продолжай с
    остальными.
11. AI-этап (`postprocess.enrich`) никогда не пишет в processed (`target`): он
    читает processed и пишет в отдельную папку enriched.
12. Очистка сирот enriched возможна только по маркеру владения `ai_hash` и не
    трогает чужие файлы vault или медиа, на которые ссылаются другие файлы.

## Архитектура

Двухэтапный конвейер с физически раздельными результатами:

```
raw/  →  processed/  →  enriched/  →  хранилище Obsidian
   импорт (без LLM)      AI-постобработка
```

- `raw` — архив исходных экспортов (только для чтения).
- `processed` — результат этапа 1 (только импорт). `_index.md` + манифест
  владения.
- `enriched` — результат этапа 2 (импорт + LLM-резюме/теги/тема/тип), папка,
  на которую указывает Obsidian. Локальные медиа копируются, чтобы хранилище
  оставалось автономным. Заметки-темы (`enriched/topics/*.md`) сливают
  несколько чатов в одну карточку знаний (см. `topics.py`).

Этап 1 (импорт, без LLM): `scan → extract → emit → manifest`
- `scan` — обход папки-источника; кандидаты — файлы с зарегистрированными
  расширениями (registry).
- `extract` — процессор типа файла формирует метаданные и сохраняет
  оригинальное тело.
- `emit` — атомарно пишет результат, копирует привязанные медиа.
- `manifest` — журнал владения; `--prune` удаляет только `old - current`.
- Инкрементальность: каждый результат несёт `source_hash` (SHA-1 сырого файла);
  неизменённые источники на следующем запуске пропускаются.

Этап 2 (`postprocess.enrich`), читает `processed`, пишет `enriched`:
- Для каждой заметки processed: разделить frontmatter/тело, прочитать
  `source_hash`.
- Копия в enriched пропускается, когда она существует **и**
  `enriched.ai_hash == processed.source_hash` — новые/изменённые источники
  идут через Ollama, уже проанализированные никогда не перевызываются.
- При успехе enriched-заметка хранит `ai_hash = source_hash`, поэтому обычный
  повторный импорт не может стереть AI-работу, а следующий запуск точно знает,
  что нужно восстановить.
- После цикла пересобирается `enriched/_index.md`.
- `--prune-enriched` удаляет заметки enriched без пары в processed, а также
  медиа, на которые ссылались только они (требуется маркер владения).

## Безопасность

### Охрана пересечения путей (`guard.py`)

Отклонить до любых действий, для каждой пары соседних этапов:

- `первый == второй`
- `второй` внутри `первого`
- `первый` внутри `второго`

Применяется трижды на каждом запуске: `(source, target)`, `(target, enriched)`
и `(source, enriched)` — последнее гарантирует, что AI-этап никогда не сможет
писать в raw. Сравнивать значения `Path.resolve()`, нормализованные по
регистру на всех платформах. Никогда не пытаться «умно» разрешить
пересечение — отказаться запускаться.

### Prune (`manifest.py`)

- Каждый файл, созданный Obsidianizer (заметки + скопированные медиа +
  `_index.md`), записывается в `.obsidianizer-manifest.json` внутри папки
  результата.
- Читать СТАРЫЙ манифест до записи нового.
- `prune(old, current)` удаляет только `OLD - CURRENT`.
- Никогда не удалять файл, которого нет в манифесте.
- Новый манифест пишется последним, атомарно (`.tmp` → `os.replace()`), только
  при успехе.
- Нет манифеста + `--prune` → ничего не удалять, просто создать текущий
  манифест.

### Запись (`emit.py`)

- Каждый выходной файл пишется атомарно: `*.tmp`, затем `os.replace()`.
- Просить неизменённые файлы через `source_hash` (без повторных вызовов LLM).
- Медиа копируется по каждой ссылке-пути, никогда не угадывается.

## Контракт LLM (`llm.py`)

- Только локальный (Ollama `/api/generate`). Никаких API-ключей и облака.
- Импорт (`summarize`): строгий контракт разбора — блок `SUMMARY:` и список
  `TAGS:`.
- AI-этап (`analyze`): расширенный контракт — блоки `SUMMARY:`, `TAGS:`,
  `TOPIC:`, `TYPE:`; недостающие блоки деградируют в пустые значения.
- Объединение в тему (`analyze_topic`): групповой контракт — блоки `NAME:`,
  `SUMMARY:`, `DECISIONS:`, `KEY_FACTS:`, `ARTIFACTS:`; блок `NAME` становится
  очищенным именем файла темы, недостающие блоки деградируют в пустые значения.
- Список моделей (`list_models`): `GET /api/tags`, только имена — содержимое
  чатов никогда не отправляется; возвращает `None`, если Ollama недоступна
  (GUI сохраняет текущую модель и показывает статус).
- Промпты редактируются из GUI (`set_prompt` / `reset_prompt` — промпты
  импорта, AI и темы, с отдельной кнопкой «восстановить стандартный»);
  встроенные дефолты (`DEFAULT_PROMPT`, `DEFAULT_AI_PROMPT`,
  `DEFAULT_TOPIC_PROMPT`) никогда не перезаписываются, а `{content}` —
  единственная точка подстановки текста файла/чата.
- Все исключения перехватываются и деградируют до пустых резюме/тегов.

## AI-постобработка (`postprocess.py`)

- `enrich(source_root=processed, target_root=enriched, llm, prune=False, ...)`.
- Никогда не пишет в `source_root`. Пропуск по `ai_hash == source_hash`.
- Локальные медиа из обрабатываемых заметок копируются в enriched (та же
  относительная структура), чтобы ссылки на картинки оставались валидными в
  хранилище Obsidian.
- `prune=True` удаляет только сироты — .md-заметки с маркером `ai_hash`, чьей
  пары больше нет в processed, и медиа, на которые не ссылается ни один другой
  файл.
- При отмене: уже записанные результаты сохраняются, а prune и пересборка
  индекса полностью пропускаются.

## Объединение в тему (`topics.py`)

- `create_topic(target_root=processed, enriched_root=enriched, rel_files, llm, ...)`.
- Сливает выбранные чаты processed в `enriched/topics/<Имя>.md`; читает
  processed, пишет только в `enriched/topics`, никогда не копирует чаты
  (ссылается на них через `[[wiki]]`).
- Выбор приходит относительными путями; принимаются только файлы с
  `source_hash`, попытки выхода за пределы папки (traversal) отклоняются.
- Один вызов LLM (`analyze_topic`) по собранному payload; бюджет символов
  распределяется равномерно по чатам. Пустой ответ модели фиксируется как
  ошибка, но не роняет процесс.
- Инкрементальность: `topic_hash` (sha1 от отсортированных `source_hash`
  выбранных чатов) — существующая тема с тем же хэшем пропускает вызов.
- После записи пересобирается `enriched/_index.md`, чтобы тема появилась в
  навигации.
- Авто-группировка: `group_all(target_root, enriched_root, llm, ...)`
  кластеризует всю коллекцию без ручного выбора. `collect_catalog` собирает
  компактные карточки чатов; `analyze_topic_map` (промпт `map_prompt`,
  контракт `TOPIC:`/`IDS:` через `parse_topic_map`) группирует их, разбивая
  большие коллекции на чанки и передавая уже известные имена тем вперёд.
  Кластеры из двух и более чатов проходят через `create_topic`
  (инкрементально); кластеры из одного чата пропускаются, существующие темы
  никогда не удаляются. `group_all()` не реэмитит внутренние события
  `create_topic` — он сам управляет прогрессом `TOPIC_*`.

## AI-чат и поисковый слой

- Чат — это НЕ поисковая система: за извлечение отвечает `search.ChatIndex`.
  Постоянный индекс в `enriched/.obsidianizer/` (index.json + embeddings.json)
  обновляется инкрементально по `source_hash` — перечитываются/переэмбедятся
  только изменившиеся заметки (семантический слой через `LLMClient.embed`,
  `/api/embed`, по умолчанию `nomic-embed-text`). Поиск возвращает топ-K (по
  умолчанию 30) кандидатов со сниппетами; ранжирование смешивает
  нормализованный лексический балл (title ≫ tags/summary > подстрока в теле,
  морфология через токен-стем-варианты) с косинусной близостью.
- `ui.run_chat_now` отдаёт модели в роли аналитика только топ-10 кандидатов
  (полный список остаётся в UI); `CHAT_FOUND` несёт детерминированные источники
  — никогда не парсятся из текста LLM. `chat_model` (по умолчанию
  `qwen2.5:latest`) — отдельная модель для чата/поиска; импортная модель
  остаётся `deepseek-r1:14b`. Модалки чата перетаскиваемы за шапку (позиция
  запоминается на сессию).

## Структура проекта

```
Obsidianizer.py/.bat  корневой лаунчер (двойной клик → GUI, установка не нужна)
src/obsidianizer/    пакет (src layout — устанавливаемый, импортируемый)
  cli.py             точка входа; разбор аргументов изолирован здесь
  config.py          приоритет: CLI > config.yml > дефолты; GUI читает и
                     пишет тот же файл (Settings.load / Settings.save, merge+атомарно)
  guard.py           охрана пересечения путей (любая пара соседних этапов)
  registry.py        расширение -> Processor
  base.py            абстрактный класс Processor
  md_processor.py    процессор Markdown (основной тип)
  llm.py             локальный LLM-клиент
  enrich.py          компоновщик frontmatter + визитки
  emit.py            атомарная запись + копирование медиа
  manifest.py        журнал владения + prune
  index.py           генератор _index.md
  postprocess.py     AI-этап: processed → enriched (медиа, prune, index)
  topics.py          объединение в тему: несколько чатов → заметка в enriched/topics
  search.py          поисковый слой чата: инкрементальный ChatIndex (лексические
                     токены + опциональные эмбеддинги) по processed → топ-K кандидатов
  models.py          датаклассы
  events.py          единый контракт событий (EventType, Event); ядро эмитит через on_event
  ui.py              GUI-фронтенд (pywebview); импортирует events; без знания о markdown/файлах
  web/               ресурсы GUI (app.html, app.js, app.css) — тёмная тема
tests/               pytest; фикстуры в tests/fixtures/
docs/                architecture, processors, development
assets/              плейсхолдер для будущих ресурсов GUI (.exe, иконки)
```

## Двуязычная документация

Пользовательская документация должна вестись одновременно на английском и
русском. Английские файлы используют стандартное имя файла; русские версии —
суффикс `.ru.md`. `README.md` — точка входа для GitHub; `AGENTS.md` —
технический контракт для кодинг-агентов; `AGENTS.ru.md` — русская копия для
человека. Программа никогда не читает файлы документации.

## Команды

```bash
python -m obsidianizer --source ./raw --target ./processed --dry-run
obsidianizer --source ./raw --target ./processed --prune   # после `pip install .`
obsidianizer ai --target ./processed --enriched ./enriched             # только AI-этап
obsidianizer ai --target ./processed --enriched ./enriched --prune-enriched
pytest                  # критически важные тесты безопасности запускаются из корня репозитория
```

## Коммиты

- Держи историю чистой и атомарной: одно логическое изменение на коммит.
- Проект должен оставаться автономным — не вендорить и не ссылаться на
  внутренности AI Chat Exporter.
