# Obsidianizer

## [0.3.3] — 27.08.2026

### Добавлено
- UI вкладки Obsidianizer (v5.12): поле «Базовый путь галереи (для проектов
  вне Vault)» с сохранением, чекбокс «Принять существующую заметку как
  заметки» (adopt), строки ⚠-изменений под устаревшими папками в таблице
  сканирования (из `changes` в `obs_scan`), подсказка для чужих заметок,
  доступных к принятию, и однострочная сводка сканирования в статус-баре.
  Значения восстанавливаются из `defaults()` и сохраняются при изменении.

## [0.3.2] — 27.08.2026

### Добавлено
- Backend вкладки Obsidianizer для паритета с v5.12: автоматическое
  определение корня vault (`_find_vault_root` поднимается до `.obsidian`),
  когда не заданы ни vault_root, ни gallery_prefix; метод бриджа
  `set_obsidianize_gallery_prefix`; `obs_obsidianize` передаёт `adopt` и
  `gallery_prefix`.
- Умное сканирование (`obs_scan`): по каждой папке список `changes` из
  скрытого манифеста карточки (`card_diff` / `format_changes` — добавлены /
  удалены / изменены файлы, структура папок, данные проекта), флаг
  `adoptable` для чужих заметок без файла заметок и однострочная сводка
  (проверено / без изменений / требуют обновления).

## [0.3.1] — 27.08.2026

### Добавлено
- Флаги `obsidianizer folders`: `--adopt`, `--gallery-prefix`, `--rel`
  (инфраструктура v5.12): принятие чужой заметки в `<имя>_заметки.md`

## [0.3.0] — 27.08.2026

### Добавлено
- Стабильная точка восстановления после катастрофического `git stash` +
  `reset --hard` (вернулись все 3 вкладки, 288 тестов зелёные). Ядро карточек
  (`obsidianize.py`) содержит структуру v5.11/v5.12 с `RENDER_VERSION = 8`
  (Folders / Files / About / Gallery / Images / Notes).
- Страховочные ссылки восстановления: ветки `recovery-pre-v5.11`
  (состояние до v5.11/v5.12) и `recovery-current-v5.11` (состояние с
  CLI/UI-частями v5.11/v5.12), плюс `backup-before-recovery` на базовом
  коммите; тег `v0.3.0`.
- Двухэтапный вывод: `processed/` (импорт) и `enriched/` (импорт + LLM).
- Постоянные настройки GUI: `config.yml` — единое хранилище путей, модели,
  переключателя Ollama и флагов prune / dry-run. `Settings.save()` сливает
  данные в существующий файл и пишет атомарно; GUI сохраняет при каждом
  подтверждённом изменении, перед запуском и при закрытии окна, поэтому
  повторно открытое окно восстанавливает ровно то состояние, в котором было
  закрыто. Каждая кнопка `Выбрать` открывает проводник в своём последнем
  каталоге с откатом на ближайший существующий родитель.
- Переключатель AI-постобработки: чекбокс «Использовать Ollama» стал
  «AI-постобработка» — Ollama трактуется как деталь реализации AI-слоя. При
  выключенном переключателе настройки модели и промпта скрыты в
  раскрывающемся блоке `#aiDetails`; при включении появляются комбо-бокс
  модели и кнопка `Изменить…`, а также серая подпись «Локальная модель через
  Ollama». Кнопки действий получили подписи: «ОБРАБОТАТЬ» показывает
  «Импорт + AI» / «Только импорт», вторичная кнопка AI — «Только повторный
  AI-прогон».
- Выбор модели и редактор промптов за переключателем AI: поле модели —
  комбо-бокс (свободный ввод + выпадающий список установленных моделей
  Ollama; свой список, а не `datalist`, поэтому каждая модель видна независимо
  от текста в поле; `list_models`, обновляется по требованию через
  `GET /api/tags`; только имена, текущая модель всегда сохраняется,
  недоступная Ollama показывает статус вместо падения UI). Кнопка `Изменить…`
  открывает модальный редактор с вкладками импорт / AI, с `set_prompt` /
  `reset_prompt` для каждого промпта (встроенные `DEFAULT_PROMPT` /
  `DEFAULT_AI_PROMPT` не перезаписываются; `{content}` остаётся единственной
  точкой подстановки).
- AI-этап (`obsidianizer ai`): читает заметки processed и пишет enriched-vault;
  инкрементален через маркер `ai_hash` — заметка пропускается, когда её
  `ai_hash` совпадает с `source_hash` из processed.
- Опции `--enriched DIR` / `--prune-enriched`; очистка сирот маркеро-зависима
  (только файлы с `ai_hash`, чьей пары нет в processed, и медиа, на которые
  ничего не ссылается).
- Гарантия разделения: пары папок соседних этапов не должны пересекаться
  (`(source, target)`, `(target, enriched)`, `(source, enriched)`).
- События AI-этапа: `AI_SCAN_STARTED`, `AI_FILE_STARTED`, `AI_FILE_DONE`,
  `AI_FILE_SKIPPED`, `AI_FILE_ERROR`, `AI_FINISHED` (заменяют старый
  `LLM_STARTED`).
- Объединение в тему («Объединить в тему…»): выбор нескольких чатов processed
  в модальном окне (чекбоксы + поиск) и слияние их в одну тему
  `enriched/topics/<Имя>.md`. Один вызов LLM даёт
  NAME / SUMMARY / DECISIONS / KEY_FACTS / ARTIFACTS и источники по сервисам
  со ссылками на исходные чаты; имя файла берётся из блока NAME модели
  (очищается от спецсимволов). Инкрементально через `topic_hash` (хэш
  `source_hash` выбранных чатов): неизменный набор пропускает вызов LLM.
  Новый шаблон `topic_prompt` (третья вкладка редактора промптов), события
  `TOPIC_*` и методы моста `list_chats()` / `create_topic()`.
- «ОБРАБОТАТЬ» теперь чистый импорт: AI-этап автоматически не запускается.
  AI работает только по явному действию — кнопка «AI-постобработка» (по
  каждому чату) или «Объединить в тему…». Подпись кнопки зафиксирована как
  «Только импорт».
- Авто-группировка («Авто-группировка»): все чаты processed автоматически
  группируются в темы без ручного выбора. Проход `map_prompt` кластеризует
  карточки чатов (название/источник/дата + фрагмент тела) в темы через блоки
  `TOPIC:`/`IDS:`; большие коллекции разбиваются на чанки по размеру payload,
  а уже найденные имена тем передаются дальше, чтобы одна тема сохраняла имя.
  Каждый кластер из двух и более чатов проходит тот же путь `create_topic`
  (инкрементально через `topic_hash`); кластеры из одного чата пропускаются,
  существующие темы никогда не удаляются. Новый шаблон `map_prompt`
  (четвёртая вкладка редактора промптов), событие `TOPIC_MAP_STARTED` и
  метод моста `group_all()`.

## [0.3.0] — Не выпущен

### Добавлено
- Десктопный GUI (`obsidianizer ui`, pywebview): выбор источника/результата,
  переключатель Ollama + модель, опции dry-run/prune, прогресс-бар, текущий
  файл, цветной журнал, итог, кнопка «Открыть результат». Чистый фронтенд
  поверх того же ядра.
- Честная остановка: `pipeline.run` получает `cancel_check` (опрос только
  между файлами; текущий файл — включая долгий вызов Ollama — доводится до
  конца).
- Гарантированный одиночный `FINISHED` на любом пути (обычное завершение,
  ошибка файла, отмена, фатальная ошибка запуска). `Report.cancelled` — только
  при пользовательской отмене; `Report.critical_error` фиксирует фатальные
  ошибки.
- Корневой лаунчер `Obsidianizer.py` / `Obsidianizer.bat`: двойной клик
  запускает GUI прямо из корня репозитория — установка пакета не нужна;
  `Obsidianizer.py --check` выводит диагностику без открытия окна.
