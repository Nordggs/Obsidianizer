# Obsidianizer

## [0.7.3] — 08.10.2026

### Добавлено
- **Дерево детекции на вкладке «Обработка» и структурный обзор (TICKET-014)** —
  вкладка «Обработка» стала управляемым потоком: Source → Detected → Overview →
  Enrichment → AI → Tools. Новое независимое дерево детекции (`#detectedTree`,
  выбрать всё / снять / инвертировать, контекстное меню с операциями над веткой,
  корень как единое целое) работает рядом с замороженным выбором файлов, а
  бэкенд предоставляет `scan_tree()` (read-only проекция SourceIndex) и
  `overview_build({selection, selection_provided})` с явными защитами
  `no_scan`/`stale_scan`/`empty_selection`/`bad_output`. Новый `overview.py`
  строит чистый, детерминированный обзор структуры без LLM (известные шаблоны
  каталогов, content-fallback для неизвестных папок, таблицы файлов,
  `[[wiki]]`-ссылки для файлов, обычные code-span для папок) и атомарно пишет
  его в `enriched/overview/`. «Обзор папок» переименован в «Общий обзор».

### Изменено
- **Resizable-области детекции и исключения на вкладке 1** — универсальный
  сплиттер и два persistent-сплиттера (файлы/дерево) в Detected; вкладка 1
  умеет снимать пользовательские исключения через контекстное меню (системные
  правила показаны серым), поля Source синхронизируются в обе стороны.

### Исправлено
- **Scan на вкладке 1 для больших деревьев** — busy-индикатор
  (`obsBusyStart`/`obsBusyStop`, анимация статуса, блокировка кнопок, остановка
  при любом исходе) и делегированные обработчики чекбоксов вместо построчных
  listeners; content-хэши считаются лениво, поэтому отсутствующие карточки не
  читают файлы.
- **Контекстное меню дерева детекции** — `stopPropagation` направляет операции
  ветки на кликнутую ветку, а не на корень; таблица вкладки 1 получила
  сворачивание по веткам (сохраняется между рендерами), иконки папок и кнопки
  свернуть-всё/развернуть-всё.

### Тесты
- 641 тест зелёный, включая новый `tests/test_ticket014_overview.py`
  (builder + матрица защит) и исполняемый JS-смоук
  `tests/test_ticket014_js.py`.

## [0.7.1] — 23.09.2026

### Добавлено
- **Принудительный Rebuild старых карточек (TICKET-003)** — новый флаг CLI
  `--rebuild`, чекбокс GUI «Пересобрать карточки» и вторая команда Templater
  «Obsidianizer Rebuild» заново генерируют свои карточки актуальным
  рендерером, даже если они считаются актуальными. В отличие от `--force`
  Rebuild никогда не перезаписывает чужие заметки (они остаются конфликтом).
  Операция — для миграции структуры, а не для обычных изменений.
- **Двойная установка шаблонов** — панель Integration устанавливает/чинит оба
  шаблона («Obsidianizer Update» и «Obsidianizer Rebuild») и показывает
  отдельный статус для каждого; окно справки и ручное извлечение поставляют
  шаблон Rebuild; ключи i18n RU+EN для нового чекбокса.

### Изменено
- **RENDER_VERSION 9 → 10** — карточки, созданные до появления колонок
  `Comments` / `Description (Auto)`, теперь определяются как устаревшие и
  мигрируют к текущей 7-колоночной таблице Files обычным `Update` с
  сохранением всех пользовательских данных (файл заметок, Comments,
  frontmatter).
- **Документация EN+RU** (`docs/obsidianize`, `README`, `AGENTS`) описывает
  Update vs Rebuild, флаг `--rebuild` и правило обязательного bump
  `RENDER_VERSION` при любом изменении структуры карточки (иначе старые
  карточки остаются `ok` и пропускаются).

### Исправлено
- Карточки, созданные старыми версиями, считались актуальными и молча
  пропускались, поэтому новые колонки `Comments` / `Description (Auto)` не
  появлялись до удаления карточки; теперь обычный `Update` мигрирует их.

### Тесты
- 592 теста зелёные, включая миграцию версии, Rebuild для своих/чужих
  карточек, сохранность Comments, флаг CLI `--rebuild`, установку/статус двух
  шаблонов, непустые поставляемые шаблоны Rebuild и ключи i18n RU+EN.

  не удаляется» (удержание по старому manifest; `_index.md` скрывает
  исключённое, не удаляя файлы/manifest). Поверхность: `config.yml`

  объектов Source (файлы + папки вкл. пустые; без Markdown в Source, без

  строится и доступен (`Report.source_index`, слой предпросмотра);
  потребители переключаются в 008/009 — поведение не меняется.
- **Enrichment Entity, аддитивное владение (TICKET-008A)** — `EnrichmentEntity`
  как логический объект (не `.md`; новый `enrichment.py` с чистыми
  конструкторами `build_entity()`/`update_entity()`): ссылки `source_id`
  пишутся аддитивно рядом со старыми ключами (manifest/`ai_hash`/topic

  SourceIndex во frontmatter, `postprocess` переносит, `search` хранит

  аддитивно и идемпотентно дописывает `source_id` в старые owned-заметки
  без ссылки (processed + enriched; `topics/`/служебное исключены как
  агрегаты). Хирургическая вставка во frontmatter (без YAML round-trip):
  тела, Comments, AI-метаданные и маркеры (`source_hash`/`process_version`/

  `no_namespace`/`source_unavailable`), без угадывания; identity во время

  (`match_continuity`: точное совпадение контент-хэша важнее size/mtime/имя;

  id-владения. `retired`/`superseded` скрыты из `_index.md` и поиска (файлы
  сохраняются до явного prune); оживший id сбрасывается в `active`.

## [0.6.8] — 16.09.2026

### Исправлено
- **Таблица Files снова корректно рендерится в Obsidian** — вики-ссылки
  изменены с `[[rel|name]]` на `[[name]]`, чтобы `|` внутри ссылки не ломал
  разбор колонок таблицы. Заголовок `Comment` переименован в

  пользователем колонка остаётся `Comments`).
- **Пропавшая колонка-разделитель в таблице Files** — 7-й `---` был сдвинут
  на позицию влево, из-за чего Modified/Size/Date схлопывались.
- **Числовые ключи frontmatter больше не роняют скан** — PyYAML (появился
  в 0.6.7) читал незакавыченные числовые свойства вида
  `50: 20:0020202:10884` как ключи-`int`, из-за чего падали
  `_user_props` / `_notes_user_hash` с ошибкой
  `'int' object has no attribute 'startswith'` и весь прогон
  `update_cards` прекращался. Теперь ключи один раз нормализуются в
  строки в `parse_frontmatter()`.
- **Изоляция ошибок по папкам** — папка, при обработке которой возникло
  исключение, теперь пишет traceback в лог, попадает в `summary.failed`,
  а обработка продолжается на остальных папках. Это разблокирует и
  GUI-скан, и Templater-хоткей, которые раньше останавливались на одной
  заметке с нестандартным frontmatter. `failed` выводится в CLI, а payload
  `OBS_FINISHED` несёт его для GUI.

## [0.6.3] — 05.09.2026

### Изменено
- **Актуальность карточек по содержимому** — fingerprint карточки
  (`obsidianizer_hash`) теперь считается по СОДЕРЖИМОМУ файлов (sha1), а не
  по `mtime`. Облачная синхронизация (Dropbox и т.п.) и фоновые процессы
  трогают mtime, не меняя ни байта, — из-за этого карточки залипали в
  `stale` (`status=stale` при `changed=0`). `mtime` остался в метаданных
  только для отображения (колонки «Изменён» / «Updated») и на решение
  «устарела ли карточка» больше не влияет. Скрытый манифест хранит
  `{path: {size, hash}}`, а `card_diff` определяет `changed` по содержимому:
  правки того же размера (AAAA→BBBB) ловятся, mtime-джиттер игнорируется.
  Одноразовый эффект: первый прогон пересобирает все карточки (смена формулы
  fingerprint); скан читает содержимое файлов и занимает чуть больше времени.

### Исправлено
- **Кнопка Up у карточек первого уровня** — карточка-прямая-дочка скан-корня
  получала голый линк `[[..|Up]]`, указывающий на родительскую ПАПКУ, которую
  Obsidian открыть не может (диалог «file already exists» при клике). Теперь
  линк ведёт на карточку корня (`../<имя корня>`), как и на всех нижних
  уровнях.

  «AI-постобработка» — Ollama трактуется как деталь реализации AI-слоя. При
  выключенном переключателе настройки модели и промпта скрыты в
  раскрывающемся блоке `#aiDetails`; при включении появляются комбо-бокс
  модели и кнопка `Изменить…`, а также серая подпись «Локальная модель через

  от текста в поле; `list_models`, обновляется по требованию через
  `GET /api/tags`; только имена, текущая модель всегда сохраняется,
  недоступная Ollama показывает статус вместо падения UI). Кнопка `Изменить…`

  `DEFAULT_AI_PROMPT` не перезаписываются; `{content}` остаётся единственной
  точкой подстановки).
- AI-этап (`obsidianizer ai`): читает заметки processed и пишет enriched-vault;
  инкрементален через маркер `ai_hash` — заметка пропускается, когда её
  `ai_hash` совпадает с `source_hash` из processed.
- Опции `--enriched DIR` / `--prune-enriched`; очистка сирот маркеро-зависима
  (только файлы с `ai_hash`, чьей пары нет в processed, и медиа, на которые
  ничего не ссылается).
- Гарантия разделения: пары папок соседних этапов не должны пересекаться
  (`(source, target)`, `(target, enriched)`, `(source, enriched)`).
- События AI-этапа: `AI_SCAN_STARTED`, `AI_FILE_STARTED`, `AI_FILE_DONE`,
  `AI_FILE_SKIPPED`, `AI_FILE_ERROR`, `AI_FINISHED` (заменяют старый
  `LLM_STARTED`).
- Объединение в тему («Объединить в тему…»): выбор нескольких чатов processed
  в модальном окне (чекбоксы + поиск) и слияние их в одну тему
  `enriched/topics/<Имя>.md`. Один вызов LLM даёт
  NAME / SUMMARY / DECISIONS / KEY_FACTS / ARTIFACTS и источники по сервисам
  со ссылками на исходные чаты; имя файла берётся из блока NAME модели
  (очищается от спецсимволов). Инкрементально через `topic_hash` (хэш
  `source_hash` выбранных чатов): неизменный набор пропускает вызов LLM.
  Новый шаблон `topic_prompt` (третья вкладка редактора промптов), события
  `TOPIC_*` и методы моста `list_chats()` / `create_topic()`.
- «ОБРАБОТАТЬ» теперь чистый импорт: AI-этап автоматически не запускается.
  AI работает только по явному действию — кнопка «AI-постобработка» (по
  каждому чату) или «Объединить в тему…». Подпись кнопки зафиксирована как
  «Только импорт».
- Авто-группировка («Авто-группировка»): все чаты processed автоматически
  группируются в темы без ручного выбора. Проход `map_prompt` кластеризует
  карточки чатов (название/источник/дата + фрагмент тела) в темы через блоки
  `TOPIC:`/`IDS:`; большие коллекции разбиваются на чанки по размеру payload,
  а уже найденные имена тем передаются дальше, чтобы одна тема сохраняла имя.
  Каждый кластер из двух и более чатов проходит тот же путь `create_topic`
  (инкрементально через `topic_hash`); кластеры из одного чата пропускаются,
  существующие темы никогда не удаляются. Новый шаблон `map_prompt`
  (четвёртая вкладка редактора промптов), событие `TOPIC_MAP_STARTED` и
  метод моста `group_all()`.
- Десктопный GUI (`obsidianizer ui`, pywebview): выбор источника/результата,
  переключатель Ollama + модель, опции dry-run/prune, прогресс-бар, текущий
  файл, цветной журнал, итог, кнопка «Открыть результат». Чистый фронтенд
  поверх того же ядра.
- Честная остановка: `pipeline.run` получает `cancel_check` (опрос только
  между файлами; текущий файл — включая долгий вызов Ollama — доводится до
  конца).

  ошибка файла, отмена, фатальная ошибка запуска). `Report.cancelled` — только
  при пользовательской отмене; `Report.critical_error` фиксирует фатальные
  ошибки.
