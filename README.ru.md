# Obsidianizer

| **Русский** | [English](README.md) |

Локальный препроцессор, который структурирует сырые материалы и готовит их к
использованию в [Obsidian](https://obsidian.md).

Укажите ему папку с сырыми файлами (сейчас — экспорт чатов в Markdown, позже —
TXT/SVG/скрипты). Этап 1 извлекает метаданные, копирует привязанные медиа и
пишет чистую самодостаточную папку импорта. Необязательный этап 2 затем
обогащает каждую заметку резюме и тегами через локальную LLM (Ollama) во
второй vault, готовый к использованию.

## Зачем

В рабочих папках накапливаются сырые экспорты — сами по себе они нормальные,
но внутри Obsidian их трудно просматривать. Obsidianizer оборачивает каждый
сырой файл блоком YAML-frontmatter и «визиткой» (резюме, теги, даты,
статистика), оставляя исходное содержимое нетронутым — и не оставляет следов в
папке-источнике.

```
сырые заметки ──> Obsidianizer ──> processed/ ──> enriched/ ──> vault Obsidian
                     │                │             │
                     │                │             └── сюда возвращается AI-этап
                     └── без LLM      └── результат импорта
 соседняя: локальная LLM (Ollama) работает только на AI-этапе
```

Две физически раздельные папки результата:

- `processed/` — результат импорта: метаданные + медиа, **никогда** не
  модифицируется LLM и AI-этапом.
- `enriched/` — результат AI-этапа: импорт + LLM-резюме/теги/тема/тип, плюс
  заметки-темы (`enriched/topics/*.md`), которые сливают несколько чатов в
  одну карточку знаний. **Именно эту папку стоит открывать в Obsidian.**
  Локальные медиа копируются сюда, поэтому хранилище остаётся автономным.

Инкрементально по дизайну: enriched-заметка пропускается, когда её `ai_hash`
совпадает с `source_hash` из processed, поэтому повторный AI-запуск вызывает
Ollama только для новых/изменённых файлов («145 пропущено, 10 обработано»), а
обычный повторный импорт физически не может уничтожить AI-результат.

## Контракт безопасности

- **Источник никогда не изменяется.**
- **Удаление происходит только через манифест владения.** `--prune` удаляет
  только файлы, созданные самим Obsidianizer; чужие файлы не трогаются никогда.
- **Пары папок соседних этапов не должны пересекаться** (совпадение путей или
  вложенность — жёсткие ошибки) — проверяется для `(source, target)`,
  `(target, enriched)` и `(source, enriched)`.
- **LLM опционален.** Если Ollama недоступна, файлы всё равно обрабатываются
  с обогащением только метаданными.
- **Очистка сирот AI-этапа маркеро-завитсима.** `--prune-enriched` удаляет
  только файлы enriched с маркером `ai_hash`, чьей пары больше нет в processed,
  и медиа, на которые не ссылается ни одна другая заметка.

Полный контракт — в `docs/architecture.md` и `AGENTS.md`.

## Установка

Требуется Python 3.10+.

```bash
pip install .            # или: pip install -e .[dev] для разработки
```

Или запуск без установки:

```bash
python -m obsidianizer --help
```

## Быстрый старт

```bash
# 1. Локальный конфиг (необязательные переопределения)
cp config.example.yml config.yml

# 2. Сухой прогон — предпросмотр того, что произойдёт
obsidianizer --source ./raw --target ./processed --dry-run

# 3. Настоящий запуск (импорт; затем AI-этап, если LLM включён)
obsidianizer --source ./raw --target ./processed --enriched ./enriched

# 4. Позже — только новые/изменённые файлы обновили vault:
obsidianizer ai --target ./processed --enriched ./enriched

# 5. Удалить файлы, которые больше не производятся (только те, что принадлежат Obsidianizer):
obsidianizer --source ./raw --target ./processed --prune

# 6. Убрать осиротевшие AI-результаты (удалённые чаты не оставляют призраков):
obsidianizer ai --target ./processed --enriched ./enriched --prune-enriched
```

### Опции CLI

```
--source DIR      папка-источник (переопределяет конфиг)
--target DIR      папка processed (переопределяет конфиг)
--enriched DIR    папка AI-результата (переопределяет конфиг)
--model NAME      модель Ollama для резюме/тегов
--no-llm          полностью пропустить LLM-обогащение
--dry-run         посчитать и показать план, но ничего не писать
--prune           удалить файлы Obsidianizer, которые больше не производятся
--prune-enriched  на AI-этапе удалить осиротевшие файлы enriched и их медиа
```

Подкоманда `folders` строит карточки проектов (см.
[Folder Obsidianizer](#folder-obsidianizer)):

```bash
# всё дерево
obsidianizer folders --path "D:\Projects\DemoProject" --force

# только одна карточка (именно это делает хоткей Templater)
obsidianizer folders --path "<папка>" --no-recursive --adopt \
    --vault-root "<vault>" --rel "<папка-относительно-vault>"
```

```
опции folders
--path DIR            папка для сканирования (обязательна)
--no-recursive        записать только карточку этой папки; карточки подпапок
                      не трогаются
--adopt               чужая заметка с именем <папка>.md переименовывается (1:1)
                      в <папка>_заметки.md, затем создаётся свежая карточка
--vault-root DIR      корень Obsidian vault — включает блок Gallery
--gallery-prefix TXT  запасной префикс пути vault для галереи, когда проект
                      вне vault
--rel TXT             vault-relative путь сканируемой папки (корректная ссылка
                      «⬆ Up» при локальном обновлении одной карточки)
--template NAME       github (Project Dashboard) | classic
--force               пересобрать даже без изменений; чужую заметку перезаписать
                      только вместе с семантикой --adopt
--dry-run             сканировать и показать план, ничего не писать
```

## Графический интерфейс (основной)

Десктопный GUI — главный способ работы с Obsidianizer. Устанавливать пакет не
нужно — запуск прямо из корня репозитория:

```bash
# Windows: двойной клик по Obsidianizer.bat (берёт .venv, если он есть), или:
python Obsidianizer.py
```

**Ярлык с иконкой**: в корне репозитория лежит `Obsidianizer.ico` — создайте
ярлык на `Obsidianizer.bat`, затем ПКМ по ярлыку → Свойства → Сменить
значок → укажите `Obsidianizer.ico`.

Диагностика без открытия окна:

```bash
python Obsidianizer.py --check
```

В окне три вкладки:

- **📁 Obsidianize** — карточки папок (см. ниже);
- **💬 Чат-обработка** — описанный ниже конвейер raw → processed → enriched:
  укажите папки источника/результата/AI-результата, включите Ollama и нажмите
  **ОБРАБОТАТЬ** — это чистый импорт, LLM не вызывается. AI-работа всегда
  явное действие: кнопка **AI-постобработка** по каждому чату,
  **Объединить в тему…**, чтобы слить выбранные чаты в одну заметку
  `enriched/topics/<Имя>.md` (имя даёт модель, неизменный набор чатов
  пропускает вызов), или **Авто-группировка**, чтобы автоматически разбить
  всю коллекцию processed на темы;
- **🤖 AI-анализ** — локальный LLM-обзор содержимого папки, записывается рядом
  с карточкой как `<папка>_обзор.md` и встраивается в секцию AI Review.

В окне — прогресс-бар, текущий файл, цветной журнал и итог. Кнопка **Стоп**
останавливает партию после завершения текущего файла — уже идущий запрос к
Ollama не прерывается. CLI остаётся доступным для автоматизации.

## Folder Obsidianizer

Вкладка Obsidianize (или `obsidianizer folders`) генерирует карточку проекта в
стиле GitHub для каждой папки рабочего дерева: `<папка>.md` рядом с файлами
папки. Секции: навигация, `Folders` (таблица подпапок с реальными
агрегатами), `Files` (единая таблица: тип, чем открывается, изменено, размер,
комментарий), `About` (поля проекта), `Gallery`, `Images`, `AI Review`,
`Notes`.

С каждой карточкой идёт парный файл **`<папка>_заметки.md`** — единственный
редактируемый пользователем слой (клиент, адрес, дизайнер, комментарии…).
Obsidianizer никогда не перезаписывает заметки; их правка помечает карточку
устаревшей, и следующее обновление пересобирает генерируемую часть со свежими
данными About.

### Частые ситуации

**В папке ещё нет карточки — там просто файлы.**
Ничего страшного: запустите Obsidianize — карточка и файл заметок появятся
сами. Пока карточки нет, это ничему не мешает, файлы работают как обычно.

**Я случайно создал заметку в Obsidian (например, Ctrl+клик по папке), а
потом запустил Obsidianizer.**
Ничего не пропадёт. Программа видит: «эта заметка не моя» — и без вашего
разрешения её не трогает, а в таблице скана подскажет, что делать. Включите
«Принять существующую заметку как заметки» (или просто обновите карточку
хоткеем — там это уже включено): ваша заметка станет файлом заметок, а на её
месте появится карточка.

**А мои заметки программа вообще не затрёт?**
Нет. Файл `<имя папки>_заметки.md` — ваша личная территория: программа
создаёт его один раз и после этого никогда не перезаписывает, что бы ни
происходило.

**Я изменил поля проекта в заметках (клиент, дизайнер…).**
Внесите правки в заметки — при следующем обновлении карточка честно покажет
«требует обновления» и подхватит новые данные. Никаких фантомных «файлы
добавлены/удалены» для неизменённых файлов.

**Обязательно ли что-то обновлять сразу?**
Нет. Карточка — просто удобная витрина; обновляйте когда удобно, хоть через
месяц. Изменённые карточки будут помечены в таблице скана.

**Я работаю в Obsidian и вообще не запускал Obsidianizer.**
С вашими файлами ничего не произойдёт: программа ничего не пишет, пока вы
сами её не запустите.

Полная структура карточки, шаблоны и сценарий работы — в
[docs/obsidianize.ru.md](docs/obsidianize.ru.md) (EN: `docs/obsidianize.md`).

## Интеграция с Obsidian (хоткей Templater)

Один хоткей обновляет карточку той папки, в которой вы находитесь. Настройка —
одна кнопка, без ручного прописывания путей:

1. В GUI укажите в поле «Папка» ваш Obsidian vault.
2. Нажмите **🔗 Obsidian Integration** — шаблон обновления скопируется в папку
   Templater, причём **путь к Obsidianizer подставится автоматически**.
3. Назначьте хоткей (например, `Alt+3`) в Obsidian: Настройки → Горячие
   клавиши → «Obsidianizer Update».

При успехе приходит Notice с самодиагностикой: `Gallery ✓/✗ · Images ✓/✗`.
Шаблон запускает CLI для папки открытой заметки (`--no-recursive`) с
`--adopt --vault-root --rel`: одно нажатие обновляет ровно одну карточку.

Плавающее окно справки (кнопка «?» → вкладка **🔗 Integration**) показывает
живой статус интеграции — vault ✓/✗, Templater ✓/✗, шаблон ✓/✗, CLI ✓ —
с кнопкой **Установить / Починить**. Собранный EXE сам работает как CLI,
поэтому установленной сборке не нужны bat-файлы и PATH. Ручная настройка по-
прежнему описана в
[obsidian/obsidianizer-refresh.md](obsidian/obsidianizer-refresh.md).

## Конфиг

`config.yml` читается, если присутствует; иначе применяются значения по
умолчанию из `config.example.yml`. Аргументы CLI всегда имеют приоритет.

## Структура проекта

```
Obsidianizer.py / .bat   точки запуска (двойной клик открывает GUI)
src/obsidianizer/   пакет (импортируемый, устанавливаемый)
tests/              набор pytest (в первую очередь критические пути безопасности)
docs/               архитектура + контракт процессоров + разработка
assets/             плейсхолдер для будущих ресурсов GUI (.exe, иконки)
```
