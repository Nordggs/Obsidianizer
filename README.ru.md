# Obsidianizer

![Obsidianizer](docs/images/Obsidianizer%20Заставка.png)

| **Русский** | [English](README.md) |

Obsidianizer — локальный инструмент для подготовки проектных материалов к
работе в [Obsidian](https://obsidian.md) — и для дальнейшей работы с ними.

Укажите на обычную папку проекта (чертежи, PDF, документы, изображения,
таблицы — Markdown не обязателен) — и она превратится в структурированную
систему карточек с навигацией, которая комфортно открывается в вашем
хранилище. А ещё приложение обрабатывает экспортированные AI-чаты в чистые
обогащённые Markdown-заметки и подключает локальную LLM (Ollama) для поиска,
обзоров и суммирования ваших материалов.

![Как работает Obsidianizer](docs/images/Obsidianizer%20схема%20fix.jpg)

## Три инструмента в одном приложении

| № | Функция | Что делает |
|---|---|---|
| ① | **Obsidianize** — основная | Превращает обычные проектные папки и файлы в удобную структуру для Obsidian: карточки, навигация, галереи |
| ② | **Chat Processing** | Обрабатывает экспортированные чаты и другие Markdown-материалы |
| ③ | **AI-анализ** | Ищет, анализирует и суммирует материалы в любой выбранной вами папке |

## Установка

Требуется Python 3.10+.

```bash
pip install .            # или: pip install -e .[dev] для разработки
```

Или без установки:

```bash
python -m obsidianizer --help
```

Portable-сборка для Windows: скачайте `Obsidianizer-x.y.z-win64.zip` со
страницы [Releases](https://github.com/Nordggs/Obsidianizer/releases),
распакуйте и запустите `Obsidianizer.exe`.

**Ярлык с иконкой**: в корне репозитория лежит `Obsidianizer.ico` — создайте
ярлык на `Obsidianizer.bat`, затем ПКМ по ярлыку → Свойства → Сменить
значок → укажите `Obsidianizer.ico`.

## Графический интерфейс (основной)

Десктопный GUI — главный способ работы с Obsidianizer — запускается прямо из
корня репозитория:

```bash
# Windows: двойной клик по Obsidianizer.bat (берёт .venv, если он есть), или:
python Obsidianizer.py
```

Диагностика без открытия окна:

```bash
python Obsidianizer.py --check
```

В окне три вкладки, соответствующие трём инструментам:

- **📁 Obsidianize** — карточки папок ([① ниже](#-obsidianize--карточки-папок));
- **💬 Chat Processing** — обработка экспортов ([② ниже](#-chat-processing--экспортированные-чаты));
- **🤖 AI-анализ** — локальный LLM-анализ ([③ ниже](#-ai-анализ--работа-с-материалами)).

В окне — прогресс-бар, текущий файл, цветной журнал и итог. Кнопка **Стоп**
останавливает партию после завершения текущего файла — уже идущий запрос к
Ollama не прерывается. CLI остаётся доступным для автоматизации.

Плавающее окно справки (кнопка **?** справа от панели вкладок) объясняет
активную вкладку простым языком, а его вкладка **🔗 Integration** показывает
живой статус интеграции с Obsidian.

## ① Obsidianize — карточки папок

**Основной инструмент.** Дайте ему обычную папку проекта:

```
Проект/
├── DWG/
├── PDF/
├── DOC/
├── изображения/
└── прочие файлы
```

— и он превратит её в Obsidian-структуру: **карточку проекта** в стиле
GitHub (`<папка>.md`) для каждой папки дерева, с навигацией, `Folders`
(таблица подпапок с реальными агрегатами), `Files` (единая таблица: тип,
чем открывается, изменено, размер, комментарий), `About` (поля проекта),
`Gallery`, `Images`, `AI Review`, `Notes`.

С каждой карточкой идёт парный файл **`<папка>_заметки.md`** — единственный
редактируемый пользователем слой (клиент, адрес, дизайнер, комментарии…).
Obsidianizer никогда не перезаписывает заметки; их правка помечает карточку
устаревшей, и следующее обновление пересобирает генерируемую часть со свежими
данными About.

Вкладка Obsidianize: **🔍 Просканировать** читает папку только на чтение и
показывает состояние каждой карточки (ok / stale / missing / conflict) со
строками ⚠-изменений; **✨ Obsidianize** создаёт и обновляет карточки;
**🔗 Obsidian Integration** связывает Obsidian ([см. ниже](#интеграция-с-obsidian-хоткей-templater)).

### Частые ситуации

**В папке ещё нет карточки — там просто файлы.**
Ничего страшного: запустите Obsidianize — карточка и файл заметок появятся
сами. Пока карточки нет, это ничему не мешает, файлы работают как обычно.

**Я случайно создал заметку в Obsidian (например, Ctrl+клик по папке), а
потом запустил Obsidianizer.**
Ничего не пропадёт. Программа видит: «эта заметка не моя» — и без вашего
разрешения её не трогает, а в таблице скана подскажет, что делать. Включите
«Принять существующую заметку как заметки» (или просто обновите карточку
хоткеем — там это уже включено): ваша заметка станет файлом заметок, а на её
месте появится карточка.

**А мои заметки программа вообще не затрёт?**
Нет. Файл `<имя папки>_заметки.md` — ваша личная территория: программа
создаёт его один раз и после этого никогда не перезаписывает, что бы ни
происходило.

**Я изменил поля проекта в заметках (клиент, дизайнер…).**
Внесите правки в заметки — при следующем обновлении карточка честно покажет
«требует обновления» и подхватит новые данные. Никаких фантомных «файлы
добавлены/удалены» для неизменённых файлов.

**Обязательно ли что-то обновлять сразу?**
Нет. Карточка — просто удобная витрина; обновляйте когда удобно, хоть через
месяц. Изменённые карточки будут помечены в таблице скана.

**Я работаю в Obsidian и вообще не запускал Obsidianizer.**
С вашими файлами ничего не произойдёт: программа ничего не пишет, пока вы
сами её не запустите.

### CLI

```bash
# всё дерево
obsidianizer folders --path "D:\Projects\MyProject" --force

# только одна карточка (именно это делает хоткей Templater)
obsidianizer folders --path "<папка>" --no-recursive --adopt \
    --vault-root "<vault>" --rel "<папка-относительно-vault>"
```

```
опции folders
--path DIR            папка для сканирования (обязательна)
--no-recursive        записать только карточку этой папки; карточки подпапок
                      не трогаются
--adopt               чужая заметка с именем <папка>.md переименовывается (1:1)
                      в <папка>_заметки.md, затем создаётся свежая карточка
--vault-root DIR      корень Obsidian vault — включает блок Gallery
--gallery-prefix TXT  запасной префикс пути vault для галереи, когда проект
                      вне vault
--rel TXT             vault-relative путь сканируемой папки (корректная ссылка
                      «⬆ Up» при локальном обновлении одной карточки)
--template NAME       github (Project Dashboard) | classic
--force               пересобрать даже без изменений; чужую заметку перезаписать
                      только вместе с семантикой --adopt
--dry-run             сканировать и показать план, ничего не писать
```

Полная структура карточки, шаблоны и сценарий работы — в
[docs/obsidianize.ru.md](docs/obsidianize.ru.md) (EN: `docs/obsidianize.md`).

## ② Chat Processing — экспортированные чаты

Chat Processing предназначен для **экспортированных чатов и других
Markdown-материалов**: он структурирует их, извлекает метаданные, копирует
связанные медиа и опционально обогащает каждую заметку резюме и тегами через
локальную LLM (Ollama).

Один из основных сценариев — обработка файлов, экспортированных приложением
**AI Chat Exporter** — это отдельное приложение и самостоятельный проект:

**[AI Chat Exporter](https://github.com/Nordggs/Project_AI_Base)**
экспортирует чаты из ChatGPT, Claude, DeepSeek, Gemini, Qwen и других
сервисов в Markdown →

```
AI Chat Exporter
       ↓  экспорт в Markdown
Chat Processing (Obsidianizer)
       ↓  структурированный материал + опциональное AI-обогащение
Obsidian vault
```

AI Chat Exporter не обязателен — подойдёт любая папка с Markdown.

### Как это работает

```
сырые заметки ──> Obsidianizer ──> processed/ ──> enriched/ ──> Obsidian vault
                    │                │             │
                    │                │             └── сюда возвращает AI-этап
                    └── без LLM      └── результат импорта
```

Две физически раздельные папки вывода:

- `processed/` — результат импорта: метаданные + медиа, **никогда** не
  трогаются LLM.
- `enriched/` — результат AI-этапа: импорт + резюме/теги/темы от LLM, плюс
  заметки тем (`enriched/topics/*.md`), объединяющие несколько чатов в одну
  карточку знаний. **Именно эту папку открывайте в Obsidian.**

Инкрементальность по дизайну: обогащённая заметка пропускается, если её
`ai_hash` совпадает с `source_hash` из processed — повторный AI-прогон
вызывает Ollama только для новых/изменённых файлов («145 пропущено,
10 обработано»), а обычный реимпорт никогда не уничтожает AI-результаты.

### Контракт безопасности

- **Источник никогда не изменяется.**
- **Удаления — только через манифест владения.** `--prune` удаляет только
  файлы, созданные самим Obsidianizer; чужие файлы не трогаются.
- **Соседние папки этапов не должны пересекаться** (совпадение путей или
  вложенность — жёсткие ошибки): `(source, target)`, `(target, enriched)`,
  `(source, enriched)`.
- **LLM опциональна.** Без Ollama файлы всё равно обрабатываются — только
  метаданные.
- **Очистка осиротевших AI-результатов — по маркеру.** `--prune-enriched`
  удаляет только enriched-файлы с `ai_hash`, чья пара исчезла из processed,
  плюс медиа, на которые не ссылается ни одна заметка.

### CLI

```bash
# 1. Локальный конфиг (необязательные переопределения)
cp config.example.yml config.yml

# 2. Пробный запуск — предпросмотр
obsidianizer --source ./raw --target ./processed --dry-run

# 3. Рабочий запуск (импорт; затем AI-этап, если LLM включена)
obsidianizer --source ./raw --target ./processed --enriched ./enriched

# 4. Позже — только новые/изменённые файлы:
obsidianizer ai --target ./processed --enriched ./enriched

# 5. Удалить файлы, которых больше нет в источнике (только свои):
obsidianizer --source ./raw --target ./processed --prune

# 6. Удалить осиротевшие AI-результаты:
obsidianizer ai --target ./processed --enriched ./enriched --prune-enriched
```

```
опции
--source DIR      папка-источник (переопределяет конфиг)
--target DIR      папка processed (переопределяет конфиг)
--enriched DIR    папка AI-результата (переопределяет конфиг)
--model NAME      модель Ollama для резюме/тегов
--no-llm          полностью пропустить LLM-обогащение
--dry-run         посчитать и показать план, но ничего не писать
--prune           удалить файлы Obsidianizer, которые больше не производятся
--prune-enriched  на AI-этапе удалить осиротевшие файлы enriched и их медиа
```

## ③ AI-анализ — работа с вашими материалами

AI-анализ — инструмент локальной LLM для **интеллектуальной работы с
материалами в любой выбранной вами папке**: результат обработки чатов, ваши
проектные папки, каталог исследований или целый vault:

- **поиск** по материалам;
- **обзор** содержимого папки — модель читает папку и пишет
  `<папка>_обзор.md`, который встраивается в секцию AI Review карточки;
- **суммирование** заметок и документов;
- **анализ** нескольких заметок вместе.

Запуск со вкладки **🤖 AI-анализ**: выберите папку, отметьте подпапки,
при желании включите содержимое текстовых файлов (подробнее, но дольше) — и
формируйте обзор. Источники не изменяются — пишутся только файлы обзора.

## Интеграция с Obsidian (хоткей Templater)

Один хоткей обновляет карточку той папки, в которой вы находитесь. Настройка —
одна кнопка, без ручного прописывания путей:

1. В GUI укажите в поле «Папка» ваш Obsidian vault.
2. Нажмите **🔗 Obsidian Integration** — шаблон обновления скопируется в папку
   Templater, причём **путь к Obsidianizer подставится автоматически**.
3. Назначьте хоткей (например, `Alt+3`) в Obsidian: Настройки → Горячие
   клавиши → «Obsidianizer Update».

При успехе приходит Notice с самодиагностикой: `Gallery ✓/✗ · Images ✓/✗`.
Шаблон запускает CLI для папки открытой заметки (`--no-recursive`) с
`--adopt --vault-root --rel`: одно нажатие обновляет ровно одну карточку.

Плавающее окно справки (кнопка «?» → вкладка **🔗 Integration**) показывает
живой статус интеграции — vault ✓/✗, Templater ✓/✗, шаблон ✓/✗, CLI ✓ —
с кнопкой **Установить / Починить**. Собранный EXE сам работает как CLI,
поэтому установленной сборке не нужны bat-файлы и PATH. Ручная настройка по-
прежнему описана в
[obsidian/obsidianizer-refresh.md](obsidian/obsidianizer-refresh.md).

### О хоткее

Obsidianizer **не назначает** горячие клавиши Obsidian автоматически и не
редактирует `hotkeys.json` вашего vault. После установки интеграции:

1. Откройте Obsidian → Настройки → Горячие клавиши.
2. Найдите команду Templater, связанную с шаблоном «Obsidianizer Update».
3. Проверьте назначенную клавишу (например, `Alt+3`) или назначьте свою.
4. Откройте карточку проекта и выполните команду.

Конкретная клавиша зависит от настроек вашего хранилища — `Alt+3` в этой
документации просто пример.

## Конфиг

`config.yml` читается, если присутствует; иначе применяются значения по
умолчанию из `config.example.yml`. Аргументы CLI всегда имеют приоритет.

## Структура проекта

```
Obsidianizer.py / .bat   точки запуска (двойной клик открывает GUI)
src/obsidianizer/   пакет (импортируемый, устанавливаемый)
tests/              набор pytest (в первую очередь критические пути безопасности)
docs/               архитектура + контракт процессоров + разработка
assets/             плейсхолдер для будущих ресурсов GUI (.exe, иконки)
```
