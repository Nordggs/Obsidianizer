# Obsidianizer

| **Русский** | [English](README.md) |

Локальный препроцессор, который структурирует сырые материалы и готовит их к
использованию в [Obsidian](https://obsidian.md).

Укажите ему папку с сырыми файлами (сейчас — экспорт чатов в Markdown, позже —
TXT/SVG/скрипты). Этап 1 извлекает метаданные, копирует привязанные медиа и
пишет чистую самодостаточную папку импорта. Необязательный этап 2 затем
обогащает каждую заметку резюме и тегами через локальную LLM (Ollama) во
второй vault, готовый к использованию.

## Зачем

В рабочих папках накапливаются сырые экспорты — сами по себе они нормальные,
но внутри Obsidian их трудно просматривать. Obsidianizer оборачивает каждый
сырой файл блоком YAML-frontmatter и «визиткой» (резюме, теги, даты,
статистика), оставляя исходное содержимое нетронутым — и не оставляет следов в
папке-источнике.

```
сырые заметки ──> Obsidianizer ──> processed/ ──> enriched/ ──> vault Obsidian
                     │                │             │
                     │                │             └── сюда возвращается AI-этап
                     └── без LLM      └── результат импорта
 соседняя: локальная LLM (Ollama) работает только на AI-этапе
```

Две физически раздельные папки результата:

- `processed/` — результат импорта: метаданные + медиа, **никогда** не
  модифицируется LLM и AI-этапом.
- `enriched/` — результат AI-этапа: импорт + LLM-резюме/теги/тема/тип, плюс
  заметки-темы (`enriched/topics/*.md`), которые сливают несколько чатов в
  одну карточку знаний. **Именно эту папку стоит открывать в Obsidian.**
  Локальные медиа копируются сюда, поэтому хранилище остаётся автономным.

Инкрементально по дизайну: enriched-заметка пропускается, когда её `ai_hash`
совпадает с `source_hash` из processed, поэтому повторный AI-запуск вызывает
Ollama только для новых/изменённых файлов («145 пропущено, 10 обработано»), а
обычный повторный импорт физически не может уничтожить AI-результат.

## Контракт безопасности

- **Источник никогда не изменяется.**
- **Удаление происходит только через манифест владения.** `--prune` удаляет
  только файлы, созданные самим Obsidianizer; чужие файлы не трогаются никогда.
- **Пары папок соседних этапов не должны пересекаться** (совпадение путей или
  вложенность — жёсткие ошибки) — проверяется для `(source, target)`,
  `(target, enriched)` и `(source, enriched)`.
- **LLM опционален.** Если Ollama недоступна, файлы всё равно обрабатываются
  с обогащением только метаданными.
- **Очистка сирот AI-этапа маркеро-завитсима.** `--prune-enriched` удаляет
  только файлы enriched с маркером `ai_hash`, чьей пары больше нет в processed,
  и медиа, на которые не ссылается ни одна другая заметка.

Полный контракт — в `docs/architecture.md` и `AGENTS.md`.

## Установка

Требуется Python 3.10+.

```bash
pip install .            # или: pip install -e .[dev] для разработки
```

Или запуск без установки:

```bash
python -m obsidianizer --help
```

## Быстрый старт

```bash
# 1. Локальный конфиг (необязательные переопределения)
cp config.example.yml config.yml

# 2. Сухой прогон — предпросмотр того, что произойдёт
obsidianizer --source ./raw --target ./processed --dry-run

# 3. Настоящий запуск (импорт; затем AI-этап, если LLM включён)
obsidianizer --source ./raw --target ./processed --enriched ./enriched

# 4. Позже — только новые/изменённые файлы обновили vault:
obsidianizer ai --target ./processed --enriched ./enriched

# 5. Удалить файлы, которые больше не производятся (только те, что принадлежат Obsidianizer):
obsidianizer --source ./raw --target ./processed --prune

# 6. Убрать осиротевшие AI-результаты (удалённые чаты не оставляют призраков):
obsidianizer ai --target ./processed --enriched ./enriched --prune-enriched
```

### Опции CLI

```
--source DIR      папка-источник (переопределяет конфиг)
--target DIR      папка processed (переопределяет конфиг)
--enriched DIR    папка AI-результата (переопределяет конфиг)
--model NAME      модель Ollama для резюме/тегов
--no-llm          полностью пропустить LLM-обогащение
--dry-run         посчитать и показать план, но ничего не писать
--prune           удалить файлы Obsidianizer, которые больше не производятся
--prune-enriched  на AI-этапе удалить осиротевшие файлы enriched и их медиа
```

## Графический интерфейс (основной)

Десктопный GUI — главный способ работы с Obsidianizer. Устанавливать пакет не
нужно — запуск прямо из корня репозитория:

```bash
# Windows: двойной клик по Obsidianizer.bat (берёт .venv, если он есть), или:
python Obsidianizer.py
```

Диагностика без открытия окна:

```bash
python Obsidianizer.py --check
```

Укажите папки источника, результата обработки («Результат обработки») и
AI-результата («AI-результат») с помощью нативных диалогов, включите Ollama,
выберите модель, при необходимости — dry-run / prune / «Удалять сироты из
AI-результата», и нажмите **ОБРАБОТАТЬ** — это чистый импорт, LLM не
вызывается. AI-работа всегда явное действие: кнопка **AI-постобработка** по
каждому чату, **Объединить в тему…**, чтобы слить выбранные чаты в одну
заметку `enriched/topics/<Имя>.md` (имя даёт модель, неизменный набор чатов
пропускает вызов), или **Авто-группировка**, чтобы автоматически разбить всю
коллекцию processed на темы. В окне — прогресс-бар, текущий файл, цветной
журнал и итог. Кнопка **Стоп** останавливает партию после завершения текущего
файла — уже идущий запрос к Ollama не прерывается. CLI остаётся доступным для
автоматизации.

## Конфиг

`config.yml` читается, если присутствует; иначе применяются значения по
умолчанию из `config.example.yml`. Аргументы CLI всегда имеют приоритет.

## Структура проекта

```
Obsidianizer.py / .bat   точки запуска (двойной клик открывает GUI)
src/obsidianizer/   пакет (импортируемый, устанавливаемый)
tests/              набор pytest (в первую очередь критические пути безопасности)
docs/               архитектура + контракт процессоров + разработка
assets/             плейсхолдер для будущих ресурсов GUI (.exe, иконки)
```
