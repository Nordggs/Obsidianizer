# Folder Obsidianizer (obsidianizer folders)

Создаёт «живые» Markdown-карточки-каталоги для любой папки: каждая папка
получает карточку `<имя папки>.md`, которая выглядит как маленький локальный
GitHub-репозиторий (шапка, навигация, дерево репозитория, README, AI-обзор,
встроенные рабочие заметки).

Два шаблона с **одинаковой структурой**:

- **`github`** (по умолчанию) — *Project Dashboard v2*: добавляет
  `cssclasses: [github-dashboard]`, чтобы прилагаемый CSS-сниппет стилизовал
  карточку как страницу GitHub (опционально).
- **`classic`** — та же структура, но без `cssclasses` (чистый Markdown,
  работает без сниппета).

**Модель данных — карточка полностью пересоздаваемая, данные живут отдельно**:

| Данные | Где живут | Что делает генератор |
|---|---|---|
| Файлы проекта (факты) | сама папка | сканируются read-only |
| Ключи пользователя (клиент, телефон, карта, …) | frontmatter карточки | **никогда не затираются**, дефолты только для отсутствующих стандартных полей |
| Рабочие заметки | отдельный файл `<папка>_заметки.md` | создаётся один раз, **никогда не заменяется**, встраивается через `![[…_заметки]]` |
| AI-обзор | отдельный файл `<папка>_обзор.md` | встраивается, когда файл есть |

**Главный контракт — папка полностью read-only**: сканер только читает имена,
размеры, даты и расширения файлов. Единственные файлы, которые когда-либо
создаются или изменяются, — карточки `.md` и производные заметки
(`*_заметки.md`, `*_обзор.md` никогда не считаются пользовательскими файлами
проекта). Исходные файлы не переименовываются, не перемещаются, не удаляются
и не конвертируются.

## Что даёт карточка (v2 — оба шаблона)

```markdown
---
дата_начала: 2026-03-16
...                          # ВСЕ ключи пользователя сохраняются (в т.ч. неизвестные, многострочные списки)
obsidianizer: true           # маркер нашей карточки
obsidianizer_hash: a1b2c3…   # отпечаток папки (свежесть)
obsidianizer_template: github
obsidianizer_version: 2      # версия рендера (повышение → авто-миграция)
cssclasses: [github-dashboard]   # только у шаблона github
---

# 🏗️ <Имя папки>

> <комментарий из frontmatter>            (или «Автоматическая карточка каталога»)
> ◉ Local project · N файлов · 52.2 MB · M папок   (компактная мета-строка)
[[../Родитель|↑ Родитель]]              (только у подпапок)

[[#📂 Code|Code]] · [[#🤖 AI Review|AI Review]] · [[#✍️ Рабочие заметки|Notes]]   (навигация)

<div class="github-langbar">…</div>       (полоска категорий с пропорциями, flex-grow)

## 📂 Code                                (дерево репозитория, 4 колонки)
| Файл | Комментарий | Изменено | Размер |
| 📁 [[Под/Под|Под]] · N файлов |  | сегодня | 1.2 MB |
| 📐 Чертежи · 2 файла |  | вчера | 3.4 MB |    (категории как виртуальные строки)

## 📖 README

### 📋 О проекте                          (только непустые поля; пользовательские ключи тоже)
| Поле | Значение |
| Клиент | ООО Ромашка |

### 📐 Чертежи                            (заголовки без расширений)
_2 файла · 3.4 MB · изменено вчера_
| Файл | Комментарий | Изменено | Размер |

### 🖼️ Галерея проекта                      (только с --vault-root)
    блок img-gallery

## 🤖 AI Review                           (только если есть <Папка>_обзор.md)
![[Папка_обзор]]

## ✍️ Рабочие заметки
![[Папка_заметки]]                       (встроено; сам файл — зона пользователя)

_Обновлено: DD.MM.YYYY HH:mm_
```

- Размеры и «изменено» — **только агрегаты** (папки/категории); мета-строка
  показывает итоги по всему поддереву.
- Дерево репозитория охватывает папки + категории; таблицы категорий в README
  показывают только прямые файлы папки.

## GitHub-вид (CSS-сниппет, опционально)

Шаблон `github` пишет в frontmatter `cssclasses: [github-dashboard]`. Чтобы
карточка реально выглядела как страница GitHub, один раз установите
прилагаемый сниппет:

1. Скопируйте `obsidian/github-dashboard.css` в папку сниппетов вашего vault:
   `<vault>/.obsidian/snippets/github-dashboard.css`.
2. Obsidian → Настройки → Внешний вид → **CSS-сниппеты** → включите
   `github-dashboard`.

Сниппет стилизует: шапку репозитория, компактную мета-строку, навигационные
пилюли, «полоску языков» категорий (цвета GitHub), таблицу `📂 Code` в рамке
файлового списка, GitHub-таблицы (моноширинные имена, приглушённые колонки
«Изменено/Размер», hover), приглушённые мета-строки и оформленные встроенные
блоки заметок/обзора. Без сниппета карточки остаются обычным Markdown —
ничего не ломается.

- Ссылки **относительные** (`[[файл.xlsx]]`), поэтому папку можно переносить
  между каталогами и vault без поломки ссылок.
- Карточка подпапки содержит ссылку `[[../Родитель|↑ Родитель]]`.
- Комментарии в таблицах и пользовательские ключи frontmatter (в т.ч.
  неизвестные генератору) переносятся между обновлениями.
- Карточка распознаётся по маркеру `obsidianizer: true`. Чужой файл с именем
  папки **не перезаписывается** (нужен `--force`).
- Повторный запуск без изменений ничего не пишет (сравнение по
  `obsidianizer_hash`).

## CLI

```bash
obsidianizer folders --path "D:\Projects\DemoProject"            # создать/обновить карточки
obsidianizer folders --path "D:\Projects\DemoProject" --dry-run  # только отчёт
obsidianizer folders --path "D:\Projects\DemoProject" --force    # перезаписать чужую заметку
obsidianizer folders --path "D:\Projects\DemoProject" --no-recursive
obsidianizer folders --path "D:\Projects\DemoProject" --no-gallery
obsidianizer folders --path "D:\Projects\DemoProject" --vault-root "D:\Obsidian\Vault"
obsidianizer folders --path "D:\Projects\DemoProject" --template classic  # та же структура, без cssclasses
```

## Обновление карточки из Obsidian

### Вариант 1 — плагин «Shell commands» (рекомендуется)

1. Установите плагин **Shell commands**.
2. Создайте команду (Settings → Shell commands → New command):
   - Название: `Obsidianizer: обновить карточку`
   - Команда: `obsidianizer folders --path "{{folder_path}}"`
3. Выполняйте команду из палитры команд (или по горячей клавише) — карточка
   текущей папки и все карточки подпапок обновятся.

### Вариант 2 — Templater-обёртка (кнопка/скрипт в заметке)

Скрипт берёт текущую папку, открывает команду плагина по Obsidian URI и
показывает путь в уведомлении:

```js
<%*
// Обновление карточки Folder Obsidianizer для текущей папки.
// Требует плагин "Shell commands" с командой id = obsidianizer-update
// (команда: obsidianizer folders --path "{{folder_path}}").
const tFile = tp.file.find_tfile(tp.file.path(true));
if (!tFile) return;
const vaultRoot = app.vault.adapter.getBasePath ? app.vault.adapter.getBasePath() : "";
const folderAbs = vaultRoot + "/" + tFile.parent.path;
app.openUrl("obsidian://shellcommands?execute=obsidianizer-update");
new Notice("Обновление карточки: " + folderAbs);
%>
```

> В плагине Shell commands id команды задаётся вручную в поле «Id» (например,
> `obsidianizer-update`) — подставьте его в скрипт.

## Ограничения и поведение

- Карточка перегенерируется, когда изменился состав/размеры/даты файлов
  папки, когда появился/исчез файл обзора `<папка>_обзор.md`, когда шаблон
  карточки отличается от `--template`, или когда `obsidianizer_version` старее
  версии рендера (миграция; ключи frontmatter и комментарии в таблицах
  сохраняются).
- Рабочие заметки: `<папка>_заметки.md` создаётся один раз — как шаблон,
  или со старым ручным блоком, мигрированным в неё (блок служит источником
  миграции только пока заметки нет). Существующие заметки **никогда не
  заменяются**.
- `*_заметки.md` и `*_обзор.md` — производные артефакты obsidianizer: никогда
  не попадают в статистику/таблицы проекта, что бы ни говорил `include_md`.
- Скрытые папки и `.obsidian`, `.git`, `node_modules`, `__pycache__`
  пропускаются; `.md`-файлы не каталогизируются (карточки — отдельный слой).
- Блок `img-gallery` генерируется только при `--vault-root` (путь в блоке
  должен быть от корня vault); изображения всегда показаны таблицей.
