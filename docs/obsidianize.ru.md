# Folder Obsidianizer (`obsidianizer folders`)

Создаёт «живые» Markdown-карточки проектов для любой папки: каждая папка
получает карточку `<имя папки>.md` в стиле локального GitHub-репозитория
(шапка, навигация, таблица подпапок, таблица файлов, карточка проекта,
галерея, AI-обзор, встроенные рабочие заметки).

Два шаблона с **одинаковой структурой**:

- **`github`** (по умолчанию) — добавляет `cssclasses: [github-dashboard]`,
  чтобы приложенный CSS-сниппет оформил карточку как страницу GitHub
  (опционально).
- **`classic`** — та же структура без `cssclasses` (чистый Markdown, работает
  без сниппета).

**Модель пользовательских данных** — карточка полностью перегенерируемая;
пользовательские данные живут вне неё:

| Данные | Где живут | Что делает генератор |
|---|---|---|
| Файлы проекта (факты) | сама папка | сканируются только на чтение |
| Пользовательские поля (проект, источник, контакт, комментарий, …) | frontmatter `<папка>_заметки.md` | **никогда не перезаписываются**; правка заметок помечает карточку устаревшей, и следующее обновление пересобирает секцию About со свежими данными |
| Рабочие заметки (тело) | `<папка>_заметки.md` | создаётся один раз, **никогда не заменяется**, встраивается через `![[…_заметки]]` |
| AI-обзор | `<папка>_обзор.md` | встраивается, когда существует |

**Главный контракт — папка полностью read-only**: сканер читает только имена,
размеры, даты и расширения. Единственные файлы, которые создаются или
изменяются, — это карточки `.md` и производные файлы (`*_заметки.md`,
`*_обзор.md` никогда не считаются пользовательскими файлами проекта).
Исходные файлы не переименовываются, не перемещаются, не удаляются и не
конвертируются.

## Структура карточки (версия рендера 8)

```markdown
---
obsidianizer: true           # маркер нашей карточки
obsidianizer_hash: a1b2c3…   # отпечаток папки (свежесть; базисонезависимый)
obsidianizer_template: github
obsidianizer_version: 8      # версия рендера (bump → авто-миграция)
cssclasses: [github-dashboard]   # только шаблон github
---

# <Имя папки>

Автоматическая карточка каталога

Local project · N файлов · M папок · РАЗМЕР
Updated DD Mon YYYY

[[#Folders|Folders]] | [[#Files|Files]] | [[#About|About]] | [[#Gallery|Gallery]]
| [[#Images|Images]] | [[#AI Review|AI Review]] | [[#Notes|Notes]]

```

Семантика секций:

- **Folders** — физические подпапки с реальными агрегатами (число файлов,
  размер поддерева, последняя правка). Первая строка — ссылка `⬆ Up`
  (только у карточек подпапок; alias-пайп экранирован `\|`, чтобы таблица
  сохраняла 4 ячейки).
- **Files** — одна таблица в стиле GitHub для прямых файлов папки,
  сортировка по расширению, затем по имени. `Opens with` — метка по
  расширению (Obsidian, AutoCAD, Excel, Word, Revit, SketchUp, CAD, `—`).
- **About** — обычный Obsidian-callout, проекция frontmatter заметок (читается
  в PDF-экспорте и вне Obsidian). Скрыт, когда поля не заполнены.
- **Gallery** — интерактивный блок `img-gallery`, генерируется только для
  прямых изображений, когда известен vault-путь (`--vault-root`, либо
  `--gallery-prefix` для проектов вне vault, либо автоопределённый корень
  vault в GUI).
- **Images** — архивный callout **только прямых изображений этой папки**
  (без рекурсии). Вложенные папки имеют собственные карточки со своими
  разделами Images. Относительные, URL-кодированные ссылки
  (`./подпапка/фото%20файл.png`) работают в любом просмотрщике.
- **AI Review** — встраивание `<папка>_обзор.md` (вкладка AI-анализ), когда
  существует.
- **Notes** — встраивание пользовательского `<папка>_заметки.md`.

Завершающий HTML-комментарий — скрытый манифест отслеживания изменений
(никогда не рендерится Obsidian) — см. [Технические заметки](#технические-заметки).

## Сценарий работы (с нуля)

1. **Откройте GUI** (`Obsidianizer.bat`) → вкладка **📁 Obsidianize**.
2. Выберите папку, оставьте «Вложенные папки» включённым, выберите шаблон,
   нажмите **✨ Obsidianize**. Каждая папка дерева получает карточку и файл
   заметок.
3. **🔍 Просканировать** показывает таблицу статусов: состояние карточки по
   папкам (ok / stale / missing / conflict), однострочную сводку и строки
   ⚠-изменений (добавлен/удалён/изменён файл, структура папок, данные
   проекта) для устаревших карточек. Если имя карточки занято чужой заметкой,
   в строке появится подсказка включить **«Принять существующую заметку как
   заметки»** (`--adopt`).
4. **Правьте пользовательские данные** в `<папка>_заметки.md` (проект,
   источник, контакт, комментарий…). Карточка не перезаписывается —
   следующее сканирование/обновление подхватит изменения.
5. **Обновление позже**: хоткей Templater на карточке (одна карточка) либо
   Obsidianize из GUI (всё дерево). Неизменённые карточки пропускаются.

### Частые ситуации

**В папке ещё нет карточки — там просто файлы.**
Запустите Obsidianize: карточка и файл заметок создадутся автоматически.
Статус такой папки в таблице скана — «missing» (нет карточки). Пока карточки
нет, работа с файлами ничем не ограничена.

**Я создал заметку в Obsidian (например, Ctrl+клик по папке), а Obsidianizer
её видит как чужую.**
Заметка, созданная самим Obsidian, не имеет маркера карточки, поэтому
программа без разрешения её не трогает — статус «conflict» (конфликт). В GUI
включите «Принять существующую заметку как заметки»: заметка переименуется в
`<папка>_заметки.md` (содержимое сохранится 1:1), а на её месте появится
свежая карточка. Хоткей Templater и Shell-команда делают это автоматически —
у них «принятие» включено всегда.

**Перезапишет ли программа мои заметки?**
Нет. `<папка>_заметки.md` создаётся один раз и больше никогда не
перезаписывается. Даже «принятие» чужой заметки срабатывает только когда
файла заметок ещё не существует.

**Я поменял поля проекта в заметках.**
Карточка честно помечается устаревшей, и следующее обновление пересобирает
секцию About с новыми данными. Файловые разделы при этом остаются точными:
никаких фантомных «добавлен/удалён» для неизменённых файлов.

**Можно ли не обновлять сразу?**
Да: карточка — витрина, а не обязательная процедура. Необновлённые карточки
помечаются в таблице скана и ждут своего часа.

**Я вообще не запускал Obsidianizer.**
Тогда программа ничего не записывала: все ваши файлы в исходном состоянии.
Никаких фоновых процессов нет — всё происходит только по явному запуску.

## Обновление карточки из Obsidian

### Хоткей Templater (основной)

1. Скопируйте `obsidian/templater/Obsidianizer Update.md` в папку шаблонов
   Templater.
2. Замените внутри путь `cli` на путь к вашему `obsidianizer-cli.bat`
   (корень репозитория).
3. Назначьте хоткей (например, `Alt+3`) → Настройки → Горячие клавиши →
   «Obsidianizer Update».

Шаблон запускает CLI для папки открытой заметки:

```
obsidianizer-cli.bat folders --path "<папка>" --no-recursive --adopt
    --vault-root "<vault>" --rel "<папка относительно vault>"
```

`--no-recursive` записывает **только карточку этой папки** (соседние не
трогаются), но агрегаты считает по полному поддереву; `--rel` держит корректной
ссылку `⬆ Up`; `--adopt` один раз превращает чужую заметку в файл заметок.
При успехе Notice сообщает самодиагностику: `Gallery ✓/✗ · Images ✓/✗`.

### Вариант 2 — плагин «Shell commands»

Создайте команду (Настройки → Shell commands → New command):

- Имя: `Obsidianizer: обновить карточку`
- Команда:
  `"C:\путь\к\obsidianizer-cli.bat" folders --path "{{folder_path}}" --no-recursive --adopt --vault-root "{{vault_path}}"`

Запуск из палитры команд или по хоткею. Оба варианта описаны в
[obsidian/obsidianizer-refresh.md](../obsidian/obsidianizer-refresh.md).

## CLI

```bash
obsidianizer folders --path "D:\Projects\MyProject"                 # всё дерево
obsidianizer folders --path "D:\Projects\MyProject" --dry-run       # только отчёт
obsidianizer folders --path "D:\Projects\MyProject" --force         # пересобрать карточки
obsidianizer folders --path "D:\Projects\MyProject" --no-recursive  # только карточка корня
obsidianizer folders --path "D:\Projects\MyProject" --no-gallery    # без блока Gallery
obsidianizer folders --path "D:\Projects\MyProject" \
    --vault-root "D:\Obsidian\Vault"                              # vault-пути для Gallery
obsidianizer folders --path "D:\Projects\MyProject" \
    --gallery-prefix "PROJECT/OBSIDIAN/Objects"             # проекты вне vault
obsidianizer folders --path "D:\Projects\MyProject" --template classic
obsidianizer folders --path "D:\Projects\MyProject" --adopt         # принять чужие заметки
```

## Оформление GitHub (CSS-сниппет, опционально)

Шаблон `github` добавляет `cssclasses: [github-dashboard]`. Чтобы карточки
выглядели как страница GitHub, установите приложенный сниппет один раз:

1. Скопируйте `obsidian/github-dashboard.css` в
   `<vault>/.obsidian/snippets/github-dashboard.css`.
2. Obsidian → Настройки → Внешний вид → **CSS-сниппеты** → включите
   `github-dashboard`.

Без сниппета карточки остаются обычным Markdown — ничего не ломается.

## Поведение

- Карточка перегенерируется, когда меняются имена/размеры/даты файлов, когда
  появляется/исчезает `<папка>_обзор.md`, когда меняются поля заметок, когда
  шаблон отличается от `--template` или когда `obsidianizer_version` старше
  версии рендера (миграция).
- `<папка>_заметки.md` создаётся один раз (как шаблон, либо с миграцией
  старого ручного блока из карточки) и после этого **никогда не
  перезаписывается**. Чужая заметка на месте карточки пропускается
  (конфликт), пока не использованы `--force` / `--adopt`.
- `--no-recursive` записывает только карточку корня, но агрегаты считает по
  **полному поддереву** — таблица Folders показывает реальные значения,
  идентичные рекурсивному запуску GUI (GUI и хоткей дают одинаковую
  карточку).
- `*_заметки.md`, `*_обзор.md` и карточки — производные артефакты: никогда не
  попадают в статистику/таблицы проекта. Скрытые папки и `.obsidian`,
  `.git`, `node_modules`, `__pycache__` пропускаются.
- Повторный запуск без изменений ничего не пишет (сравнение отпечатка).

## Технические заметки

Детекция изменений должна работать независимо от того, из какого корня
выполнен скан (GUI сканирует корень проекта, хоткей Templater — саму папку
карточки), поэтому всё ключуется в **базисе папки карточки**:

- `folder_fingerprint` хеширует пути относительно папки карточки
  (`F:<rel>·<размер>·<mtime>`, подпапки, наличие обзора) — одинаков для
  одной и той же папки, отсканированной из любого корня.
- Манифест хранит ключи файлов относительно папки карточки плюс поле `base`
  (rel папки карточки от корня обновления, для диагностики).
- `card_diff` выравнивает старые манифесты (без `base`) детерминированным
  правилом префикса: если хотя бы один сохранённый ключ несёт префикс корня
  скана, префикс отрезается у всех ключей — без эвристик.
- `obs_scan` пишет в `obsidianizer.log` diff каждой устаревшей карточки
  (корень скана, rel папки, счётчики added/removed/changed) для разбора
  post-mortem.
